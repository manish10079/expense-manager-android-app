ExpenseTracker — AMOLED Purple design system

Rendered preview of the proposed token system. Colours are the exact hex values from the audit; typography uses the app's bundled Google Sans. Layouts are reconstructions for comparison, not screenshots.

fonts + spacing: Google Sans · card radius 20dp · screen padding 20dp · tabular figures on all amounts

01 Token foundation

Brand hue held at ~254° (royal violet) instead of the current 250°, which reads slightly "generic SaaS blue". Purple 500 is a fill colour — it is never body text, because it lands at 4.48:1 on black.

05 Components

Every interactive control in one place, so states can be compared side by side rather than screen by screen.

Buttons

Primary is #7A52FF→#5B2FD6 with a white label at 4.69:1. The outlined button's border is #66617A — 3.56:1, which satisfies WCAG 1.4.11. The current #2A2A2A border sits at 1.5:1 and is effectively invisible.

What this is not. These are reconstructions from the token values, not screenshots of your app. The BEFORE frame re-creates the current values in Color.kt; layout, spacing, and icon choices are my own reconstruction and may differ from the real screens. Contrast figures are exact for flat colours — values over gradients, glows, or blur composites can only be certified on a rendered device.
